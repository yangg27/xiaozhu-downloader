### 5 项严重缺陷（均已修复 + 实测验证）
1. **插队成功率仅 50%**：挤掉受害者后空位被"等待更久"的普通任务抢走 →
   改为在同一 `_cv` 临界区**直接预占空位**给插队任务。实测 3/6 → **8/8**
2. **排队调度不公平**：`acquire_slot` 里「有空位就直接占」排在公平性检查**之前**，
   t1 完成后 t3（后加入）抢走 t2（先加入）的槽位。改为有空位时先让给等待更久者
3. **tracker 列表被 HTML 污染**：`cf.trackerslist.com` 有时返回站点 HTML，
   `parse_trackers` 只按行切分不校验 → 153 条里 130+ 条是网页源码。
   加 `_TRACKER_URL_RE` 校验 + `MIN_VIABLE_TRACKERS=5` 阈值 → 净化后 122 条合法
4. **任务删除后 tmp 目录被重建**：线程还在跑，`rmtree` 后立刻被 `ensure_dir` 重建。
   改为先 `_stop` + `join(3s)` 再删
5. **重启恢复未复用 tid**：`add_task` 新增 `tid` 参数直传构造函数（废弃"先建成再改名"补丁），
   `load_jobs` 加 `dedupe=False` 防同 URL 任务被合并

### 测试基础设施自身缺陷（12 处，关键教训）
- **Windows `SO_REUSEADDR` = Linux `SO_REUSEPORT`**：占不住端口，测端口顺延必须用
  `SO_EXCLUSIVEADDRUSE`
- **`http.server` 强制 latin-1 响应头**：裸中文 Content-Disposition 会导致服务端
  抛 UnicodeEncodeError + 客户端 `RemoteDisconnected`。测中文文件名必须用 RFC 5987
- **AES 测试不能依赖 cryptography**（本机 pip 源没有）：改为给测试服务器内置纯 Python
  加密器 + NIST 官方向量核对，反而覆盖了 frozen 版实际走的兜底路径
- `lapi.port` 是配置端口（不变），顺延结果在 `actual_port`
- 硬编码假数据（A1 曾返回 `A.get("conns", 0), 0`）必须清除 —— 违反"以实测数据为准"
